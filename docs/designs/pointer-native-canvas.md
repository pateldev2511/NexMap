## Problem (user brief, 2026-07-03)

Both designer canvases (flat network designer + rack designer) must be mouse
AND touchpad friendly. All interaction edge cases handled, with logical proof
(tests), never "trust me it works." Less distracting chrome; everything doable
in-canvas ("have everything can be done inside the canvas too, like drag and
drop options for connections, and other experiences like that"). FossFLOW-
inspired feel, all code from scratch, everything runs locally.

## Audit evidence driving this plan

- Two pointer-capture regressions already shipped (Phase 8 latent capture bug
  that broke 5 gestures; v0.6.1 rack pan stealing clicks). Zero tests dispatch
  WheelEvent/PointerEvent/TouchEvent across 61 unit files + 2 e2e specs.
- The two designers have OPPOSITE wheel semantics: flat = wheel-pan +
  ctrl/pinch-zoom (Canvas.tsx:402-418); rack = wheel-always-zoom, no pinch
  distinction (committed: RackRow.tsx:243-250, factor 1.1; the uncommitted
  RackCanvas.tsx worktree diff adds a second wheel-always-zoom handler). No
  deltaMode normalization anywhere.
- THREE gesture implementations, not two: Canvas.tsx (flat), RackCanvas.tsx
  (rack focus editor), and RackRow.tsx (~260-272: its own pan + pointer-capture
  code, 4 client-px threshold). All three become consumers of the shared core.
- 11 provable edge-case gaps (see Error Registry in the review): no
  pointercancel handling; Cmd+Z fires model-undo inside text inputs
  (App.tsx:306-327); undo-during-drag corrupts positions via stale dragOrigins;
  silent rejected rack drops (RackDesigner.tsx:368 discards FitResult); Escape
  cannot cancel rack cable drag; stale flat<->iso projection closures
  (Canvas.tsx:465-497); rack thresholds in SVG units (20x feel variance across
  zoom); ghost marquee (no e.buttons check); justMarqueed click swallow; stale
  rack fit on rack switch; dead library filter pills (RackDesigner.tsx:699-704).

## Chosen approach (user-approved)

Considered and rejected (outside-voice finding 9, user re-confirmed B): a
minimal version (11 point fixes in place + extract only normalizeWheel + a

### Wheel contract (all three canvases)

| Preference mode | Plain wheel | Ctrl/Cmd+wheel or pinch | Shift+wheel | Pan fallbacks (always) |
|---|---|---|---|---|
| `auto` (DEFAULT) | per-event heuristic: trackpad-classified events pan, mouse-classified zoom | zoom at cursor | horizontal pan | Space+drag, middle-drag, right-drag, Hand tool |
| `trackpad` | pan (both axes) | zoom at cursor | horizontal pan | Space+drag, middle-drag, right-drag, Hand tool |
| `mouse` | zoom at cursor | zoom at cursor | horizontal pan | Space+drag, middle-drag, right-drag, Hand tool |

`wheelMode: 'auto' | 'trackpad' | 'mouse'` (outside-voice finding 4, accepted):
`auto` classifies per event — fractional deltas, nonzero deltaX, or ctrlKey-
pinch signature -> trackpad semantics; large integer notch deltas (|deltaY|
>= ~100, deltaX 0, deltaMode 0/1) -> mouse semantics. Classifier is a pure
function, unit-tested against the recorded fixtures. The explicit override
exists because heuristics misread some hardware; the laptop+sometimes-mouse
user gets correct behavior on both devices without opening Settings.
Momentum-tail swallow: after Escape-cancel or modal-open, inertial wheel
events are ignored until sign-change or 150 ms of quiet.

Space+drag pan (DA-DES-5.1's explicit fallback, already implemented on the
flat canvas via `spaceHeld`) is a first-class state in the shared machine and
extends to BOTH rack canvases; middle-drag pan is kept everywhere. This is the
documented vertical-pan path for `mouse` mode, where plain wheel zooms.

- Preference lives in `src/lib/prefs.ts` (same pattern as `getConnectMode()`),
  surfaced in SettingsDialog next to the connect-mode setting. `auto`'s
  trackpad classification matches the existing flat-canvas behavior and the
  PLAN.md DA-DES-5.1 contract.
- Migration note: rack users lose wheel-zoom-by-default (intentional; it
  violated DA-DES-5.1). One-line changelog entry + the Settings toggle
  restores it via `mouse` mode.
- Normalization: `normalizeWheel(e)` converts deltaMode LINE(1)->x16 px,
  PAGE(2)->x100 px, then clamps |delta| to <=120 px per event BEFORE applying
  zoom factor `Math.pow(1.0015, -delta)`. Pinch events (ctrlKey, typical
  |deltaY| 0.5-3) pass through unclamped below the cap; discrete wheel notches
  (|deltaY| ~100-150) hit the cap, giving ~1.2x per notch. The 120 px clamp
  applies to the ZOOM branch only; the pan branch uses normalized but
  unclamped deltas (fast free-spin wheel scrolling stays fast). Unit-tested
  with recorded real-device sequences: captured via a dev-only normalized-
  event logger behind a `?debug=input` URL flag, checked in as JSON fixtures
  under `src/input/__fixtures__/`.
- Unified scale bounds: MIN 0.1, MAX 4.0 (flat's current bounds; rack's floor
  widens from 0.2 -> 0.1 — visible but harmless change). One `zoomAt(vp,
  factor, screenX, screenY)` signature; rack/viewport.ts's incompatible
  `(vp, px, py, factor)` is retired. API break is internal only.

### Gesture state machine

- Pure-function core: `reduce(state, normalizedEvent) -> {state, effects[]}`.
  No DOM access inside the machine — this is what makes it provable (see Proof
  harness). Thin DOM adapters per canvas own capture/listeners only.
- SHAPE (outside-voice finding 6, decided): a shared LIFECYCLE SKELETON
  (idle -> armed -> threshold -> active -> commit/cancel, plus pan/pinch/wheel
  states) owns the capture/cancellation/e.buttons/threshold invariants; each
  canvas contributes a typed gesture TABLE (flat: drag/marquee/lasso/link/
  relink/resize/waypoint/shape; rack: device-move/cable/marquee; row:
  pan/drill). NOT one union machine spanning ~15 gesture kinds. The fuzz
  invariant runs against the skeleton, so every canvas inherits the
  no-stuck-gesture guarantee.
- KEYBOARD ROUTER (outside-voice finding 5, accepted): one window keydown
  owner in `src/input/`; the active canvas registers its machine; routing
  order = gesture-cancel -> canvas shortcuts -> app shortcuts. The three
  existing competing listeners (App.tsx:337, Canvas.tsx:378, RackDesigner.tsx
  :254) consolidate onto it in M1. This is where "Escape cancels the
  innermost thing" and "undo aborts the drag first" become enforceable.
- First-class cancellation: `pointercancel` and `lostpointercapture` are
  transitions to `none` with cleanup effects; Escape cancels the innermost
  active thing only (gesture -> armed state -> selection, one per press).
- `e.buttons` validated on every move (kills ghost marquee/pan residue).
- Second-pointer policy, decided per state AND pointer type (outside-voice
  finding 8, accepted): pointerType 'touch' second finger during an active
  gesture -> CANCEL the gesture (revert the item) and enter PINCH — the
  universal touch escape hatch (tldraw/FigJam pattern), decided now so M4a
  never reopens the transition table. On idle touch canvas -> two pointers
  enter PINCH directly. pointerType 'mouse'/'pen' second button mid-gesture
  -> ignored (captured gesture keeps ownership).
- Thresholds in CSS px (converted from SVG user units wherever a canvas
  applies a scale transform) before the machine sees them: 4 px click-vs-drag
  (flat parity), same value for rack marquee/cable arming (replaces the
  6 SVG-unit threshold whose feel varied 20x across the zoom range).
- Wheel handler scoped to the canvas surface, not the root container: events
  whose target sits inside floating chrome (toolbar, minimap, zoom bar,
  panels) are not consumed, fixing the current flat-canvas bug where
  scrolling over the toolbar pans the canvas (Canvas.tsx:402-418 listens on
  the root div).
- Safari trackpad pinch: handle `gesturestart`/`gesturechange`/`gestureend`
  (preventDefault + map scale delta to zoomAt) in the adapter, since Safari
  emits proprietary gesture events for pinch; ctrlKey-wheel remains the
  Chromium/Firefox path.
- Right-drag pan extends to both rack canvases for parity with flat
  (contextmenu suppressed after a right-drag, same `suppressMenu` pattern).

### Proof harness (the jsdom problem, solved by construction)

jsdom does not implement pointer capture or real layout, so the plan does NOT
dispatch PointerEvents at jsdom DOM. Three layers instead:

1. UNIT (vitest, no DOM): the pure state machine is fed recorded normalized
   event sequences (mouse drag, trackpad pan, pinch, touch two-finger, cancel
   mid-drag, Escape, second-pointer attack) and asserted transition-by-
   transition. This is where every edge case in the registry gets its proof.
   Plus a FUZZ spec: thousands of random event sequences asserted against
   two invariants — the reducer never throws, and from any state a
   pointercancel/Escape pair always returns to `none` with no residual
   armed/capture effects (the "no stuck gesture, ever" guarantee).
2. ADAPTER UNIT (vitest + jsdom): `normalizeWheel`, threshold conversion, and
   the capture-wrapper are tested with synthetic events; capture calls are
   asserted via spies (jsdom's setPointerCapture absence is exactly why the
   adapter wraps it).
3. E2E (Playwright, chromium): real gesture specs — wheel pan/zoom both
   designers (mouse.wheel +/- ctrl), marquee (extend the existing rack-multi
   marquee drag spec; add a flat-canvas one), drag-port cabling (unblocked by
   stable `data-testid` on port rects), rejected-drop flash, Escape cancel.
   PLUS capture-regression specs that pin the historically buggy DOM-adapter
   layer (outside-voice finding 2, accepted): (a) start a drag, move the
   pointer outside the element/window, assert tracking continues and commits;
   (b) the v0.6.1 regression as a named spec — rack pan must not steal the
   subsequent click; (c) the Phase 8 regression class — capture target is the
   svg, not a parent. Layer 1 proves the machine; THESE prove the layer with
   the 2-for-2 shipped-bug record.
   Touch: Playwright touchscreen emulation (`hasTouch` context) for tap/drag;
   pinch via CDP `Input.synthesizePinchGesture`. If pinch synthesis proves
   flaky in CI, pinch stays covered at layer 1 with real recorded sequences
   and that exception is documented in the spec file header.

FIXTURE PROVENANCE (outside-voice finding 1, accepted): hand-authored
synthetic fixtures are the CI baseline and are labeled `synthetic: true`;
real-device traces (Mac trackpad two-finger + pinch, discrete-wheel mouse)
are recorded ONCE by the developer via the `?debug=input` logger — a named
HUMAN step inside M1, hardware inventory: the dev's own Mac + mouse. Touch
traces recorded when a touch device is available; until then touch fixtures
are synthetic-labeled. Synthetic fixtures prove machine logic; real traces
prove the normalizer against actual hardware. The distinction is never
blurred.

SAFARI EXCEPTION (outside-voice finding 3, accepted): the Safari
`gesturestart`/`gesturechange` pinch branch is UNPROVABLE UNDER THIS HARNESS
(Playwright's WebKit is not Safari and does not emit those events). It ships
with unit coverage of the mapping function only, plus a manual QA checklist
item in the release notes. Named exception, not silent.

### Intentional behavior changes (enumerated — this plan CHANGES behavior)

All existing tests must pass, AND these deliberate changes ship with new tests:
1. Rack wheel: zoom-by-default -> pan-by-default (pref restores old feel).
2. Rack zoom floor 0.2 -> 0.1.
3. Escape: no longer clears selection while cancelling a marquee/gesture.
4. Cmd+Z (and App-level Cmd shortcuts) in text fields -> native text behavior,
   not model undo; `isTextTarget` gains SELECT.
5. Rejected rack drop/nudge: silent no-op -> red flash + reason.
6. Rack gesture thresholds: SVG-units -> screen px (feel change at zoom != 1).
7. Undo during active drag: aborts the drag cleanly first.

## Quiet canvas — concrete spec (M3)

- Selection toolbar (floating, near selection, both designers): flat = align/
  distribute (absorbs AlignBar), bring/send, group, delete, color; rack device
  = nudge U up/down, unmount, delete, move-to-rack; rack cable = color swatch,
  label, length, delete (this IS the in-canvas cable ops item).
- Idle demotion: mode toolbar and zoom bar drop to 60% opacity (WCAG-safe
  floor; 40% was rejected — outside-voice finding 10b) after 4 s without
  pointer activity over them; full opacity on hover/use AND on keyboard
  focus; the active tool indicator is never demoted; honors
  prefers-reduced-motion (no fade animation, instant states). No layout
  shift, opacity only (no motion in peripheral vision — Figma UI3 lesson).
- Collapsible: Inspector and BottomPanel get collapse toggles with state
  persisted in prefs; default state unchanged (no surprise removal).
- Nothing is deleted from the UI in M3 except the dead library filter pills;
  everything else is demoted or collapsed, reversibly.
- In-canvas cable ops rationale: the brief's "everything can be done inside
  the canvas too" is broader than creation-only; cable edit/delete currently
  requires the schedule panel, which is precisely the panel-round-trip the
  brief objects to. Reviewer flagged this as expansion-shaped; user brief
  language keeps it baseline.

## Vision

### 10x Check
NexMap becomes the tool where any pointing device just works, in either
designer, with identical muscle memory. The input core is platform
infrastructure: the same pure state machine later drives PEN input and
ISOMETRIC-mode gestures with no rewrite (touch ships now, in scope). FossFLOW's
